# V4.21.0 — Sofia character photographs

Text and Live use the same portrait planner and private image store. The canonical `sofia-avatar.PNG` is always the first reference. Generated pictures never replace avatar assets.

## Behavior

- Explicit requests for Sofia selfies, mirror selfies and outfits prepare an image job. Normal conversation skips the classifier unless image/outfit terms occur.
- Sofia acknowledges with “Gib mir einen kleinen Moment.” No progress element appears in the chat.
- The browser starts the image job separately; Live context does not wait for image generation.
- Completed images appear as thumbnails, with a modal and JPEG download. Opening a thumbnail selects it as the reference for subsequent variants.
- Outfit context uses the date and night/morning/day/evening period in Europe/Berlin. Within a period the outfit stays consistent unless the user explicitly changes it. New periods permit a different outfit.
- An explicit variant retains its source outfit across date boundaries, unless clothing is explicitly changed. A variant does not replace the current daily outfit state.
- Requests combining a photograph and a task mutation ask for separate requests to avoid silently dropping an action.

## Server and storage

Existing authenticated `/api/chat` handles generation and private image delivery; `/api/live-context` prepares Live jobs. No extra API function, credentials in the browser, public image bucket or permanent personality-memory writes are introduced.

Uses the existing `OPENAI_API_KEY`, `KV_REST_API_URL` and `KV_REST_API_TOKEN`. Default image model is `gpt-image-2`; optional `SOFIA_IMAGE_MODEL` can select another compatible GPT Image edits model. This is an API call billed to the existing OpenAI API account, independent of a ChatGPT subscription. The account must have image-model access.

`vercel.json` bundles the master file into the chat function and allows 300 seconds. Provider timeout is 220 seconds. JPEG output is limited to 700 KB decoded so private Redis values remain under about 1 MB. Oversized/invalid outputs are rejected without publishing them.

The latest 20 images are retained in separate Redis portrait keys. Older images are deleted; download important images. Jobs expire after 24 hours. A global leased lock and persistent job status prevent overlapping or repeated execution of the same job. Failed or uncertain jobs are not automatically retried. Only a new explicit request can create another paid job.

## Verification

Run `node --test tests/*.test.mjs` and syntax-check changed JavaScript. Mocked tests check canonical master bytes, additional source reference, Berlin periods, outfit continuity, same-job concurrency, failure non-replay, private delivery and integration ordering. Existing task, calendar and half-duplex regression tests remain active. No paid provider call is made by tests.

Production acceptance after deployment, in a signed-in session:

1. Text: “Sofia, mach bitte ein Selfie von dir.” Expect acknowledgment, then thumbnail, working modal and download.
2. “Dasselbe Outfit in wärmerem Licht.” Compare face and clothing; only requested lighting should change.
3. Explicitly request a new outfit. Repeat a selfie during the same Berlin period; outfit should stay consistent.
4. Open an older thumbnail and request a lighting variant. Verify that selected picture is used.
5. Live: request a mirror selfie in German. Verify that listening/half-duplex behavior remains stable while the thumbnail arrives.
6. Reload the app: retained images should restore without another generation.
7. Verify date/time boundary and an explicit earlier-image variant across that boundary.
8. Trigger an unavailable model in a non-production test configuration: an error must appear with no fabricated finished image and no automatic paid retry.

Visual face consistency and actual model access require a real production generation; mocked tests cannot establish those outcomes.
