# V4.22.0 — shared character life and natural photographs

Sofia uses one fictional everyday context in Redis for Text, Live and photographs. This is separate from user long-term memories and generation failures. No avatar, audio, microphone, WebRTC or lipsync timing changes are included.

The context uses Europe/Berlin date and time. Its baseline moves through breakfast, weekday university or weekend city time, a café lunch break, afternoon activities, an evening out, home and bedtime. At 23:00–06:00 the default is home/in bed. Date/slot changes refresh the situation. Outfit and hairstyle remain continuous within their time period, with modest variation at time/date boundaries. Explicitly described current character activities can update the stored situation, so a café conversation is followed by a café selfie. Earlier daily details are superseded by the current context. Character role descriptions are not claims of verified real-world activity; explicit questions about the character's nature remain answered honestly.

Every image still uses `sofia-avatar.PNG` first. Prompts preserve facial geometry and master hair color, allow slight expressions/gestures/poses and modest hairstyles, and ask for casual phone snapshots rather than studio/editorial photographs. Existing source images remain additional references for explicit variants. No visible figcaption or subtitle is rendered; alt text and accessible button labels remain.

## Proactive photographs

Only an active, suitable personal conversation can trigger an unsolicited photo. The selector defaults to false and excludes practical tasks, calendar actions, technical/sensitive conversations and rejection. No unsolicited bedtime photos are generated. A reserved job is announced with “Warte kurz, ich zeig’s dir.” No user confirmation is required. There are no timers or photo messages while nobody is conversing.

A Redis Lua reservation uses one shared sorted set for both Text and Live. At most two unsolicited jobs can be reserved in any rolling 60 minutes, including across reloads/devices. The cap is an upper bound, not a target. Reservations expire from the rolling window at exactly 60 minutes. Reservation failures suppress the offer. Failed reserved jobs conservatively consume their slot and are never automatically retried. Explicit user requests do not consume this quota.

Generated images and friendly failure notices retain the V4.21.2 conversation anchors. Failure details never become input to new photo requests. Images still use protected authenticated delivery and retain the latest 20 generated photographs.
